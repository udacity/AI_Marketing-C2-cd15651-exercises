# Worked Demo — Set Up a Project Workspace, Build Your First Deliverable

*The real content: the finished walkthrough the demo produces.*

## A project folder is a persistent workspace

Create a folder for Vessl's summer launch and put [`brand-voice-guide.md`](../exercise/starter/brand-voice-guide.md) and [`campaign-context-sheet.md`](../exercise/starter/campaign-context-sheet.md) in it. Point Claude Code at them — a short `CLAUDE.md` that says "always work from these files" is enough. Now every request in this folder works from that context; you never re-paste your brand guidelines again.

## Files become grounding

Ask Claude Code to draft the campaign messaging brief. It pulls positioning ("Hydration, handled"), tone (encouraging, clear, a little witty), and audience (active, health-aware, 25–45) straight from the files — the brief is built from Vessl's actual voice, not a generic guess.

## Save it, then refine in place

Write the brief to a file in the folder (e.g., `messaging-brief.md`) and refine it over a couple of turns — tighten a key message, adjust the tone. The file is the deliverable, edited in place rather than buried in a scroll of chat.

## The payoff compounds

In the same session, ask for something that builds on the brief. Claude Code already has the brand and the brief from the folder — no re-pasting. Each new deliverable reuses the workspace's context and the files already on disk.

## It persists

Close the session, reopen the folder later, and the files and context are all still there — the campaign picks up where it left off.

## Key takeaway

A Claude Code project folder turns a one-off answer into a workspace where a whole campaign can live, on-brand and connected.
