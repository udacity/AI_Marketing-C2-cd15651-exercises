# Demo — Set Up a Project Workspace, Build Your First Deliverable

*Instructor demo brief. Estimated running time ~10 minutes. The full worked version is in [`../solution/walkthrough.md`](../solution/walkthrough.md).*

## Setup

- **Scenario:** Vessl (a smart water bottle) is running a creator-led summer launch. The marketer sets up a Claude Code project workspace so the whole campaign's work stays on-brand and connected.
- **Tool:** Claude Code — an interactive session in a project folder that holds the campaign's files.
- **Inputs:** [`brand-voice-guide.md`](brand-voice-guide.md) and [`campaign-context-sheet.md`](campaign-context-sheet.md), kept in the project folder as persistent context.

## What the demo demonstrates

1. Create a project folder for the campaign and put the brand-voice guide and campaign-context sheet in it. Point Claude Code at them (via a `CLAUDE.md` or an opening instruction) so every request works from that context.
2. Ask Claude Code to draft the campaign messaging brief — point out that it pulls positioning, tone, and audience from the files on its own, without you pasting them.
3. Save the brief as a file in the folder and refine it in place across a couple of turns.
4. In the same session, ask for something that builds on the brief — Claude Code already has the brand and the brief from the folder, so nothing gets re-pasted.
5. Reopen the folder in a new session and show the files and context are all still there.

## Key takeaway

A Claude Code project folder is a persistent workspace: load the brand once, and every deliverable builds on it — on-brand and connected — instead of starting cold each time.
